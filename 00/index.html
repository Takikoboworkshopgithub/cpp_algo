0. 本講の目標

この講習会では、アルゴリズムやデータ構造などを勉強します。プログラムは、同じ結果を出すコードでも以下の違いがあります。

  • すぐに終わるコード
  • \(N\) が大きくなると急に遅くなるコード
  • \(N\) が少し大きくなるだけで、現実的な時間では終わらなくなるコード

例えば、「1からNまでの和」を求めることを考えてみましょう。

■ 方法1：1つずつ足す

int N;
cin >> N;

long long ans = 0;

for (int i = 1; i <= N; i++) {
    ans += i;
}

cout << ans << endl;

この方法では、\(N\) 回足し算を行います。つまり、\(N\) が大きくなるほど計算量も増えていきます。

■ 方法2：公式を使う

1から \(N\) までの和には、 \[ 1+2+\cdots+N=\frac{N(N+1)}{2} \] という公式があります。 

long long N;
cin >> N;

long long ans = N * (N + 1) / 2;

cout << ans << endl;

こちらは、\(N\) がどれだけ大きくなっても、基本的に決まった回数の計算で答えを求められます。

同じ「1から \(N\) までの和」を求めるプログラムでも、計算方法によって効率が大きく違うことが分かります。
秋学期では、このような「どうすれば、もっと少ない計算で答えを求められるか？」という視点を身につけていきます。

1. 計算量とは

1.1 プログラムの「速さ」を考える

プログラムの効率を考えるとき、重要になるのが計算量（計算量オーダー）です。計算量は、入力サイズが大きくなったときに、必要な計算量がどのように増えていくかを表す指標の一つです。
競技プログラミングでは、主に \(O(N)\) のように表します。この \(O(...)\) はオーダー記法（Big O記法）と呼ばれます。

まずは、「Nが大きくなったとき、計算量がどのくらい増えるのか」を表していると考えてください。

for (int i = 0; i < N; i++) {
    cout << i << endl;
}

では、ループが \(N\) 回実行されます。したがって、このコードの計算量は \(O(N)\) です。

cout << N << endl;

のようなコードは、\(N\) の大きさに関係なくほぼ一定回数の処理で済みます。このような計算量を \(O(1)\) と表します。

1.2 実際に計算量を見積もってみよう

春学期の資料では、計算量についてさらに詳しく説明しています。
計算量についての資料はこちら

このサイトを使って、以下のコードを見ながら「このプログラムは何回くらい処理をするのか？」を考えてみましょう。

for (int i = 0; i < N; i++) {
    cout << i << endl;
}
for (int i = 0; i < N; i++) {
    for (int j = 0; j < N; j++) {
        cout << i << " " << j << endl;
    }
}

1.3 よく出てくる計算量

競技プログラミングでは、次の計算量をよく目にします。

計算量 イメージ
O(1)Nが増えてもほぼ一定
O(log N)Nが増えても非常にゆっくり増える
O(N)Nに比例して増える
O(N log N)Nより少し速く増える
O(N^2)Nの2乗に比例して増える
O(2^N)Nが増えると急激に増える

特に、\(O(1), O(\log N), O(N), O(N\log N), O(N^2)\) は今後の講習会で頻繁に登場します。

2. O(log N) と O(N log N)

2.1 「log N」はとても小さい

ここからは、特に重要な \(O(\log N)\) について見てみましょう。

N log_2 N
10約 3.32
10,000約 13.29
100,000,000約 26.58

\(N\) が10から1億まで増えているのに、\(\log N\) は3程度から26程度までしか増えていません。これが、「log Nはうれしい」と言われる理由です。

2.2 二分探索

例えば、\(1 \sim N\) の中から目的の値を探すことを考えます。

for (int i = 0; i < N; i++) {
    if (a[i] == target) {
        // 発見
    }
}

とすれば、最悪の場合 \(N\) 個すべてを調べる必要があります。つまり \(O(N)\) です。
しかし、データがソートされているなら、二分探索で探索範囲を半分ずつ減らしていけます（\(N \rightarrow N/2 \rightarrow N/4 \rightarrow \dots\)）。計算量は \(O(\log N)\) になります。これは第03講「二分探索」で詳しく扱います。

2.3 ソート

春学期にも登場した sort も重要です。

sort(a.begin(), a.end());

一般的に std::sort の計算量は \(O(N\log N)\) です。\(O(N)\) よりは大きいものの、\(O(N^2)\) と比べるとかなり効率的です。
秋学期では、「\(O(N^2)\) では間に合わない。では、どうすれば \(O(N\log N)\) や \(O(N)\) にできるか？」を考える機会が増えていきます。

3. 制約から計算量を考える

3.1 問題文の「制約」に注目する

競技プログラミングでは、問題文に「制約：\(1 \le N \le 100,000\)」といった表記があります。これは「\(N\) は最大で10万まで大きくなる」という重要情報です。 

for (int i = 0; i < N; i++) {
    for (int j = 0; j < N; j++) {
        // 処理
    }
}

これは \(O(N^2)\) です。\(N = 100,000\) のとき \(N^2 = 10^{10}\) となり、非常に大きな計算量になります。そのため、\(N \le 100,000\) なのに \(O(N^2)\) のアルゴリズムを使うのは避けるべきだと判断できます。

3.2 「制約 → 計算量 → アルゴリズム」

競技プログラミングの基本思考フロー：

問題文を読む ➔ 制約を見る ➔ 必要な計算量を考える ➔ 使えそうなアルゴリズムを考える ➔ 実装する

  • \(N \le 100\) なら \(O(N^2)\) でも十分間に合う
  • \(N \le 100,000\) なら \(O(N^2)\) は厳しい
  • \(N \le 1,000,000\) なら \(O(N\log N)\) や \(O(N)\) のアルゴリズムを検討する

まずは「Nが大きいなら、計算量の小さいアルゴリズムが必要」という感覚を身につけましょう。

5. vector

大量のデータをまとめて管理するときに使うのが vector です。

#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> a = {3, 1, 4, 1, 5};

    cout << a[0] << endl;
    cout << a[2] << endl;
}

5.1 vectorに要素を追加する

vector<int> a;

a.push_back(10);
a.push_back(20);
a.push_back(30);

// 要素数は a.size() で取得可能
for (int i = 0; i < a.size(); i++) {
    cout << a[i] << endl;
}

6. 二次元配列

表のようなデータを扱うときには、二次元の vector が便利です。

#include <bits/stdc++.h>
using namespace std;

int main() {
    // 3行 × 4列 の配列を作成
    vector<vector<int>> a(3, vector<int>(4));

    a[0][0] = 10;
    a[1][2] = 20;

    for (int i = 0; i < 3; i++) {
        for (int j = 0; j < 4; j++) {
            cout << a[i][j] << " ";
        }
        cout << endl;
    }
}

7. sort

データを小さい順（昇順）・大きい順（降順）に並べ替えたいときは sort を使います。

vector<int> a = {5, 2, 8, 1, 3};

// 小さい順（昇順）: 1 2 3 5 8
sort(a.begin(), a.end());

// 大きい順（降順）: 8 5 3 2 1
sort(a.rbegin(), a.rend());

8. set

同じ値を重複して持たず、集合として管理したいときには set が便利です。

set<int> s;

s.insert(10);
s.insert(20);
s.insert(10); // 重複は無視され {10, 20} となる

if (s.count(10)) {
    cout << "存在します" << endl;
}

s.erase(10); // 削除

※ set は要素の追加・削除・検索を \(O(\log N)\) 程度で行えます。

9. map

「ある値に対して、別の値を対応させたい」ときや「出現回数を数える」ときに map を使います。

9.1 出現回数を数える

#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> a = {1, 2, 1, 3, 2, 1};
    map<int, int> cnt;

    for (int x : a) {
        cnt[x]++;
    }

    // cnt[1] = 3, cnt[2] = 2, cnt[3] = 1 となる
}

10. 「どの道具を使えばいい？」

やりたいこと 使うもの
データを順番に大量に持ちたいvector
表・グリッドを扱いたいvector<vector<T>>
データを並べ替えたいsort
重複をなくして値を管理したいset
値と値を対応させたいmap
出現回数を数えたいmap

今後は「vector ➔ sort ➔ 二分探索」のように、複数の道具を組み合わせて問題を解いていきます。
