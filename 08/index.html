「行けるところまで」探索する。
Stackと再帰を使って、状態をたどろう。

★ 状態を持ちながら探索する全探索にも使える ★

0. DFSとは

DFS（Depth-First Search：深さ優先探索）は、BFSと同じくグラフを探索するためのアルゴリズムです。 BFSがスタート地点から距離の近い頂点から順番に調べるのに対し、DFSは 進めるところまで進み、行き止まりになったら戻るように探索します。

グラフの到達可能な頂点を調べる用途ではBFSでもDFSでも実装できます。 ただし、最短距離を求めたい場合は、辺の重みがすべて同じならBFSが適しています。 DFSで最初に見つけた経路が最短経路になるとは限りません。

DFSが特に役立つ場面の一つが全探索です。 01講で学んだように、現在の状態から次の状態を作り、条件を確認しながら探索を進める問題に向いています。 まずは基本的なDFSの実装を確認しましょう。

BFSとDFSの探索イメージ

BFS

近い頂点から順番に探索

DFS

進めるところまで深く探索

DFSのポイント：Stackまたは再帰を使い、現在の頂点から先へ先へと探索する。 探索順は隣接リストの順序にも左右されます。

1. DFSのStackによる実装

06講で学んだBFSでは、Queueを使って、先に追加した頂点から取り出していました。 ここでQueueをStackに置き換えると、DFSの探索を実装できます。

Stackは、後から追加した要素を先に取り出すLIFO（Last In, First Out）のデータ構造です。 そのため、直前に発見した頂点を優先して調べる動きになります。 

// DFS のためのデータ構造
vector<bool> visited(N, false);
stack<int> st;

// 初期条件（スタート地点を格納）
visited[START] = true;
st.push(START);

// Stack が空になるまで探索
while (!st.empty()) {
    int cur = st.top();
    st.pop();

    // cur から辿れる頂点をすべて調べる
    for (int nv : G[cur]) {
        if (visited[nv]) continue;

        // 訪問済みにして Stack に追加
        visited[nv] = true;
        st.push(nv);
    }
}

Stackから頂点を取り出し、その頂点に隣接する未訪問の頂点をStackに追加します。 Stackが空になるまで繰り返すことで、スタート地点から到達できる頂点を探索できます。

BFSとDFSの違いを整理すると、次のようになります。

項目BFSDFS
データ構造QueueStack
取り出し順先に入れたものから後に入れたものから
探索の特徴近い頂点から探索深い方向へ探索
最短距離辺の重みが同じなら求められる最初に見つけた経路は最短とは限らない

2. 再帰を用いたDFS

DFSは再帰関数を使っても実装できます。 現在の頂点から隣接する未訪問の頂点へ移動し、その先の探索が終わるまで処理を続けます。 Stackを明示的に用意しなくても、関数呼び出しの仕組み（コールスタック）が探索の状態を管理します。 

// DFS のためのデータ構造
vector<bool> visited(N, false);

void dfs(int cur) {
    // 訪問済みにする
    visited[cur] = true;

    // cur から辿れる頂点をすべて調べる
    for (int nv : G[cur]) {
        if (visited[nv]) continue;

        // 再帰的に探索
        dfs(nv);
    }
}

// 探索開始
dfs(START);

dfs(nv)を呼び出すと、まず頂点nvを起点とした探索に移ります。 その探索が終了すると、呼び出し元に戻り、次の隣接頂点を調べます。

再帰呼び出しのイメージ

dfs(1)
└─ dfs(2)
└─ dfs(4)
└─ dfs(5)
└─ dfs(3)
└─ dfs(6)

一つの分岐の探索が終わると、呼び出し元に戻って次の分岐を調べます。

AtCoderなどで、関数をmainの外に定義しにくい場合は、ラムダ式で再帰関数を書く方法もあります。 次の例では、selfを通して自分自身を呼び出しています。 

vector<vector<int>> G(n + 1);
vector<bool> seen(n + 1, false);

auto dfs = [&](auto self, int v) -> void {
    seen[v] = true;

    for (auto next_v : G[v]) {
        if (!seen[next_v]) {
            self(self, next_v);
        }
    }
};

// 頂点1から探索
dfs(dfs, 1);

3. DFSを使った全探索

DFSでは、再帰呼び出しを使うことで最初から現在までの状態を引き継ぎながら探索できます。 グラフの頂点をたどる場合なら、スタートから現在の頂点までに通った経路を保持できます。

経路を保存しながら探索する例

1
1 → 2
1 → 2 → 4
1 → 2 → 5
1 → 3
1 → 3 → 6

各頂点に到達した時点で、そこまでの経路を取り出せます。

例えば、dfs(4)が呼び出されたときには、引数pathに{1, 2}が渡されています。 そこに現在の頂点4を追加すれば、{1, 2, 4}という経路になります。 

void dfs(int cur, vector<int> path) {
    // 現在の頂点を経路に追加
    path.push_back(cur);

    // 現在までの経路を表示
    for (int v : path) {
        cout << v << " ";
    }
    cout << endl;

    // 隣接する未訪問の頂点へ進む
    for (int nv : G[cur]) {
        if (visited[nv]) continue;

        visited[nv] = true;
        dfs(nv, path);
    }
}

このコードは、各再帰呼び出しにpathのコピーを渡しています。 そのため、子の探索で経路に追加した頂点が、親側のpathに影響しません。 なお、ここでは説明を簡潔にするため、グラフが木である場合を想定しています。 

// 木のグラフで、頂点1から探索する場合
visited[1] = true;
dfs(1, {});

4. DFS全探索の例題：ABC114 C - 755

ここまでの考え方を使って、次の問題をDFSで解いてみましょう。

AtCoder Beginner Contest 114 C - 755 ➔

この問題では、3・5・7だけを使って作られた整数のうち、3・5・7がそれぞれ1回以上登場し、 さらに整数がN以下であるものを数えます。

ここでは、現在作っている整数と、3・5・7をそれぞれ使ったかどうかを状態として持ちます。 例えば、現在の整数が35なら、状態は(true, true, false)です。 次に3・5・7のどれかを末尾に追加し、その新しい状態を次のDFSに渡します。

状態を引き継いで数字を追加する

現在の状態

35

(true, true, false)

次に作る状態

353 / 355 / 357

(T,T,F) / (T,T,F) / (T,T,T)

末尾に追加した数字に応じて、使用済みフラグを更新します。

3・5・7をすべて使った整数が見つかったら答えに加算します。 また、現在の整数がNを超えた場合、それ以降に数字を追加してもさらに大きくなるため、その分岐は終了できます。 

#include <bits/stdc++.h>
using namespace std;

long long N;
int cnt = 0;

void dfs(long long num, bool has_three, bool has_five, bool has_seven) {
    // Nを超えたら、この先を探索する必要はない
    if (num > N) return;

    // 3・5・7をすべて使っていれば答えに加える
    if (has_three && has_five && has_seven) {
        cnt++;
    }

    // 次の桁に3・5・7を追加する
    dfs(num * 10 + 3, true, has_five, has_seven);
    dfs(num * 10 + 5, has_three, true, has_seven);
    dfs(num * 10 + 7, has_three, has_five, true);
}

int main() {
    cin >> N;

    dfs(0, false, false, false);

    cout << cnt << endl;
}

最初は整数0、3・5・7をまだ使っていない状態から始めます。 再帰呼び出しのたびに末尾へ数字を追加し、フラグを更新します。 このように、状態を引数として渡すと、探索中の情報を明示的に管理できます。

オーバーフローについて：この問題の制約では、Nの上限は10⁹なので、 10桁程度まで生成した時点でNを超えます。long longで整数を保持すれば安全に扱えます。

bit全探索のような考え方でも解けますが、この問題では「数字を1桁ずつ追加する」という状態遷移を DFSで直接表現できます。状態管理が複雑な問題では、DFSで書くと処理の流れを追いやすく、 デバッグしやすい場合があります。

bit全探索による実装例 ➔

状態管理を伴うDFS全探索は、慣れるまでは難しく感じるかもしれません。 まずは「状態として何を持つか」「次にどの状態へ遷移するか」を紙に書き出してから実装してみましょう。

5. まとめ

今回の内容を整理しましょう。

DFS

進めるところまで深く進み、行き止まりになったら戻る探索アルゴリズム。

Stack

後から入れた要素を先に取り出すデータ構造。DFSを反復処理で実装できる。

再帰

関数呼び出しを利用して、現在の頂点から先の探索を表現できる。

状態管理の全探索

現在の状態を引数で渡しながら、次の状態を再帰的に調べられる。

DFSは最短距離を求めるための手法というより、探索の過程や状態遷移を扱う場面で力を発揮します。
