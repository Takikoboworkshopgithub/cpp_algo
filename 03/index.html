0. 二分探索とは

今回は二分探索です！

二分探索は、ソート済みの配列内の要素を高速に求める手法のことです。 ソートされている、つまり小さい順番のことを昇順といいます。二分探索は、昇順であることが条件です。 以下のような問題を考えてみましょう。

例：[10, 20, 30, 40, 50, 60, 70] から、50 が格納されたインデックスを見つける

index 0
10
index 1
20
index 2
30
index 3
40
index 4
50
index 5
60
index 6
70

まずは、実直なコードとして考えてみましょう。

NUM = 50;
array = [10,20,30,40,50,60,70];
for(int i = 0; i < array.size(); i++){
    if (array[i] == NUM){
        return i;
    }
}
return -1;//見つからなかったときに-1を返すのはプログラムあるある

これにかかる計算量は、配列の要素数を N として、O(N) です。 つまり、配列が大きくなればなるほど、見つけるのにかかる時間も比例していくという感じです。

このように、前から順番に探索していくようなアルゴリズムを、線形探索といいます。 この線形探索を用いて、以下の問題を解いてみてください。

Typical Algorithm - 二分探索の問題 ➔

1. 二分探索のマインド

さて、二分探索は、全体を二分し、探索していく手法のことです。 二分した中のどっちにあるかを見て、どんどんその範囲を狭めていきます。 さっきの例を、二分探索のマインドで見てみましょう。

探索範囲を半分にする

10 20 30 40 50 60 70

index = 3 の 40 を確認 → 60 は index > 3 にある

↓
50 60 70

新しい範囲は 4 <= index <= 6

↓
50 60 70

index = 5 の 60 を確認 → 発見！

arrayの要素数は7です。これのちょうど真ん中は、index = 3 の40ですね。 さて、探したいものは60なので、見つけたいものは index > 3 にあります。 なので、新しい範囲を[50,60,70]の、4 <= index <= 6として、その真ん中のindex = 5の値を見ます。 array[5] = 60なので、これより左側にあることがわかります。

条件は、index > 3 かつ index < 5より、見つけたいものは 4 <= index <= 4になりました。 array[4] = 50なので、無事発見です。

ポイントは、「真ん中を見て、どちら側に答えがあるかを判断し、必要な範囲だけを残す」ことです。

2. 二分探索をコードにする

マインドは分かったところで、これをコードに落としてみましょう。 今までやっていたことは、探したい領域の左と右を表す変数、その真ん中にあたる数値、 あとは条件分岐でそれより左にあるのか右にあるのかをみてあげることです。

これを、「左と右が一致し発見できなくなった場合か、見つけたい値が存在し成功する」まで繰り返すアルゴリズムです。

では、実際のコードです。

NUM = 50;
left = 0;
right = array.size() - 1;
left <= 探したいインデックス <= right

while(left!=right){
    mid = (left + right)/2;//medium,つまり真ん中の値
    if(array[mid]){
        return mid;
    }
    else if(NUM < array[mid]){
        //つまり、探したい値より真ん中の数が大きい場合。この場合は新しい範囲がleft <= 探したいインデックス < midより、left <= 探したいインデックス <= mid -1
        right = mid - 1;
    }
    else if(array[mid] < NUM){
        //つまり、探したい値より真ん中の数が小さい場合。この場合は新しい範囲がmid < 探したいインデックス <= rightになるので、mid + 1 <= 探したいインデックス <= right
        left = mid + 1;
    }
}

return -1;//見つからなかった場合

left

探したい領域の左端

mid

left と right の真ん中

right

探したい領域の右端

このようにして、二分探索が実行できました。計算量は、O(logN)です。

3. 計算量はなぜO(logN)？

O(N)は、Nに比例してプログラムの実行時間がかかるということでした。 O(logN)も同様に、logNに比例して実行時間がかかるということになります。なんでlogなのかを説明しましょう。

二分探索は、while文を回すたびに要素数が半分になっていきます。 では、最初の数がNで、その数が偶数なら半分に、奇数なら+1して半分にする作業を、最終的に1になるまで繰り返すとします。 これにかかる作業回数はどれくらいでしょう。

8 -> 4 -> 2 -> 1
9 -> 5 -> 3 -> 2 -> 1
10 -> 5 -> 3 -> 2 -> 1
...
14 -> 7 -> 4 -> 2 -> 1
15 -> 8 -> 4 -> 2 -> 1
...
100 -> 50 -> 25 -> 13 -> 7 -> 4 -> 2 -> 1
...
1024 -> 512 -> 256 -> 128 -> 64 -> 32 -> 16 -> 8 -> 4 -> 2 -> 1

このようにみていくと、Nが増えても作業回数は爆発的に伸びないことがわかります。 高校数学の知識を使うと、計算回数をcntとして、最初の数をNとすると、

\(2^{x-2} \le N - 1\) を満たす最大の \(x=cnt\)

とわかります。係数や小さい引き算を外してあげると、概算として \(2^{cnt} = N \Leftrightarrow logN = cnt\)より、計算量はlogNになります。

logNは、Nが非常に大きくなっても変化量が小さくなるという特徴を持っています。 実際、\(10^9\)や\(10^{10}\)などの配列の長さに対しても、この二分探索では30回ほどの参照で済んでしまいます。

ソート済みであることが条件ですが、これを満たしていれば実行時間を大幅に減らすことができるのです！ ちなみに、C++などで採用されている配列にかかるソートの計算量はO(NlogN)で、これも半分で探索していくような工夫が凝らされています。

ここまでの要点：1回で探索範囲を半分にできる → 必要な回数はlogN程度になる

Ex. めぐる式二分探索

先述した二分探索は、[left,right]の範囲内を探索するようなアルゴリズムでした。 先週の累積和のように、[left,right)のほうが都合がよいことが度々あります。

さきほどの書き方は、問題が複雑になるにつれて、leftやrightの意味をしていることや、最終的にその変数がどのような値になっているかがわかりにくいという欠点や、 バグった時に対処がしづらい欠点があります。また、問題によって+1,-1を付け替えるのが少し面倒です。

区間のイメージ

ok ─────────────── ng

「ok は条件を満たす」「ng は条件を満たさない」という状態を維持する

leftをok、rightをngと置き換えて、以下のコードを見てみましょう。 NUM以下の最大の値を探すコードは以下の通りです。 

ok = -1;
ng = array.size();
NUM = ...;
while(abs(ng - ok) > 1){
    mid = (ok + ng)/2;
    if(条件を満たした)
        ok = mid
    else
        ng = mid
}

return ok;

すっきりしたコードになったはずです。okは必ずNUM以下の数となっていて、ok=-1としているので、array[0]がNUMより大きかった場合は-1を、array[N-1]<=NUMの場合はN-1が返ってきます。

この場合、返り値は条件を満たすギリギリの値になっています。 例えば、NUM以上の最小の値を探したい場合には、ok = N;ng = -1と置き換えるだけで値が返ってきます。

ok

条件を満たすことが確定している側

ng

条件を満たさないことが確定している側

4. lower_bound, upper_bound

C++には、標準ライブラリに二分探索を実行してくれる関数が存在します。使い方とその意味を簡単に紹介します。 

#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> a = {0, 10, 13, 14, 20};
    // aにおいて、12 以上最小の要素は 13
    cout << *lower_bound(a.begin(), a.end(), 12) << endl; // 13

    // 14 以上最小の要素は 14
    cout << *lower_bound(a.begin(), a.end(), 14) << endl; // 14

    // 10 を超える最小の要素は 13
    cout << *upper_bound(a.begin(), a.end(), 10) << endl; // 13
}

使い方

*lower_bound(配列.begin(), 配列.end(), 値)

「値」以上の最小の値

*upper_bound(配列.begin(), 配列.end(), 値)

「値」を超える最小の値

先頭に * を付ける必要があります。

最初は自分で二分探索に慣れるためにコードを書いたほうがいいですが、慣れてきたらこのような関数を活用しましょう！
